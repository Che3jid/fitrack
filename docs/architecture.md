# 架构与阶段边界

## 当前阶段

第四阶段已实现首次设置、今日、我的、饮食、训练、体重、趋势、本地备份及持久化。`main.ts` 负责 hash 路由及首次使用守卫，页面负责交互和展示，`ProfileService` 负责资料，`RecordService` 负责日常记录，`dailySummary` 与 `buildTrends` 从原始记录派生统计，`BackupService` 负责可校验的完整导出、导入及一次恢复。

## 依赖方向

```text
页面 / 公共组件 → 业务服务 → 存储接口 → 本地适配器 / 未来云适配器
                        → domain 纯计算与模型
```

`domain` 不导入 DOM、localStorage 或网络 API。`pages/`、`components/`、`services/`、`storage/` 按职责分层，不引入状态管理框架。

存储接口统一异步。`LocalRepository` 使用单个 localStorage 文档整体保存，避免资料、体重和目标部分写入。读取时检查 schemaVersion、资料、日期、记录唯一性、所属用户及数值，拒绝损坏或未知版本并保留原始数据；未来版本必须显式实现迁移。

记录通过稳定随机 ID 标识，包含 userId、schemaVersion、createdAt、updatedAt。当前没有云账号，未来本地用户标识也不作为服务端授权凭据。支持 Web Locks 的环境串行处理跨标签页写入；不支持时只保证同一仓库实例内串行写入，局域网 HTTP 预览应避免多个标签页同时编辑。

## 规划路由

| Hash 路由 | 用途 |
| --- | --- |
| #/onboarding | 首次设置 |
| #/today | 今日概览 |
| #/diet | 四餐记录 |
| #/diet/edit | 新增或编辑食物 |
| #/training | 训练记录 |
| #/training/edit | 新增或编辑训练 |
| #/weight | 每日体重 |
| #/weight/edit | 新增或修改指定日体重 |
| #/trends | 体重、摄入和热量差趋势 |
| #/profile | 个人资料 |
| #/profile/edit | 编辑资料 |
| #/backup | 导出、导入及恢复本地数据 |

使用 hash 路由，静态托管无需服务端路由回退。无资料时除备份页外的路由进入首次设置，允许新设备先导入备份；有资料时未知路由回到今日。记录路由使用 date 查询参数，食物/训练编辑使用 id 定位；日期在 UI、业务和存储边界分别校验。趋势使用 days 与 end 查询参数，限制为 7、30、90 日且不能选择未来日期。首次设置和编辑资料复用同一表单模块。

## 数据迁移与可恢复删除

存储键沿用 `fittrack.state.v1`，文档版本升至 2。版本 1 先校验、补齐 foods/trainings/days 集合，在内存中使用，下一次成功的整体写入才升级持久化文档。实体版本仍为 1。拒绝未知版本或损坏数据，不清空或部分覆盖。

记录通过 deletedAt 实现软删除，按日期提供恢复入口；汇总和当前体重选择排除已删除记录。食品变更撤销受影响日期的“记录完成”状态。记录名称经 HTML 转义，不能当作标签或脚本解析。

## 趋势与备份

趋势服务按日历日期生成连续序列，读取展示区间前 6 天以计算窗口开头的 7 日平均。体重平均只使用有效体重，摄入平均只使用已完成日期；缺失保持 `null`。图表是无第三方依赖的 SVG，遇到缺失值断线，未完成日期用空心点提示临时数据，并提供精确数值表作为可访问性后备。

备份格式有独立的 `format`、`version`、`units`、`timezone` 和 `exportedAt` 头。导入限制为 20 MB，先解析并通过与本地存储相同的完整结构校验，再展示摘要；用户明确确认后才整体替换。替换与恢复都复用仓库事务和原子写入语义。应用只保存最近一次导入前的数据作为单层 `recovery`，导出时排除该副本，防止递归增长。预览后若当前数据改变则拒绝导入，导入后若数据改变则拒绝直接恢复，避免覆盖未核对的新记录。

## 数据约束

- 日期键为 Asia/Shanghai 下的 YYYY-MM-DD，时间戳为 ISO 8601。
- WeightEntry、DailyPlan、DayStatus 按 userId + date 唯一。
- FoodEntry 保存本次食用总量；TrainingEntry 暂只支持手动估算。
- DailyPlan 保存计算结果、输入快照及算法版本，不根据最新个人资料重算过去。
- 当天资料变更更新当天目标；补录过去的体重不能误写当前资料体重，需按日期决定当前体重。
- 每日汇总从原始记录派生，不额外存储重复统计。
- DayStatus 区分尚未记录、记录中、已完成；有记录不自动等于已完成。
- 完成但无食物记录代表显式零摄入；没有食物且未完成代表缺失值。
- 较新的有效体重驱动当前资料与今日目标；删除最新记录则回退，全部删除则保留最后已知资料体重。历史目标不回算。
- 补录过去饮食/训练不伪造当年的计划快照；无计划日期的热量差为缺失，趋势保留此语义。
- 数据导入校验备份格式版本、schemaVersion、单位、时区、日期、范围、所有者和 ID；旧 schema 复用既有迁移，失败不修改当前数据。

## 验收顺序

1. 工程能运行，测试与生产构建通过。
2. 资料保存重启不丢失，当前目标与历史目标隔离。
3. 饮食、训练、体重增删改后汇总正确刷新。
4. 日历窗口、平均口径、缺失值、备份替换与单次恢复正确。
5. 创建远程开源仓库、CI、部署，再验证 HTTPS 下的 PWA。
