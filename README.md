# FitTrack

一个手机优先的开源健身饮食记录项目。网页端使用 HTML、CSS 和 TypeScript；iPhone 端使用 SwiftUI、WKWebView 和 HealthKit，并复用同一套界面与本地数据逻辑。

GitHub 仓库：[Che3jid/fitrack](https://github.com/Che3jid/fitrack)。产品名称为 FitTrack，仓库名为 `fitrack`。

## 当前进度

**本地数据库版本。** 已实现首次设置、个人资料、饮食/训练/体重记录、今日实时汇总、7/30/90 日趋势、动态 TDEE 试算与每日摄入建议，以及本地 JSON 备份与恢复。资料和记录保存在浏览器 IndexedDB 数据库中，刷新或关闭后重新打开同一地址仍会保留。

饮食按四餐管理，训练手动记录时长和消耗，体重每日一条；均可按日期查看、编辑、删除和恢复。趋势保留缺失日期，不把缺失当成零；摄入的 7 日平均只统计用户明确标记完成的日期。备份导入会先展示摘要，确认后完整替换本地数据，并保留最近一次导入前的恢复副本。

## V1 功能规划

- 首次设置：性别、年龄、身高、体重、活动水平和健身目标。
- 今日：BMR、TDEE、目标热量、摄入、预计消耗、热量差与三大营养素。
- 记录足够时：根据近 28 天完整饮食和体重趋势，显示保守的动态 TDEE 试算及目标摄入参考值。
- 饮食：早餐、午餐、晚餐、加餐的食物增删改。
- 训练：类型、时长及手动填写的估算消耗。
- 趋势：体重、摄入、热量差与 7 日平均值。
- 我的：修改资料和目标；本地数据导出、导入。

不包含 AI 食物识别、社交或复杂食物数据库。

## 技术栈

- HTML + CSS + 严格模式 TypeScript，无 UI 框架。
- [Vite](https://vite.dev/guide/)：开发服务器和生产构建。
- [Vitest](https://vitest.dev/guide/)：纯计算模块单元测试。
- Git / GitHub：版本控制；CI 在后续阶段配置。
- IndexedDB：按资料、食物、训练、体重、每日状态和目标快照分集合保存，以事务保证一次更新完整写入；业务服务只依赖异步存储接口。
- SwiftUI + WKWebView：提供原生 iPhone App 外壳，并在构建时把网页产物打包进 App。
- HealthKit：已加入权限桥接，为后续读取 Apple Watch 同步到 iPhone 的体重、步数、心率、运动和活动能量做准备。

## 运行

需要 Node.js 24 LTS（随附 npm）。在项目根目录执行：

```sh
npm ci
npm run dev
```

打开终端输出的本地地址。不能直接双击 `index.html` 运行 TypeScript 源码。

```sh
npm run test        # 单次测试
npm run test:watch  # 开发时持续测试
npm run typecheck  # 类型检查
npm run build      # 类型检查并构建到 dist/
npm run preview    # 预览已经构建的产物
npm run check      # 测试、类型检查和构建
```

Mac 与 iPhone 连接同一可信局域网后，可以执行 `npm run dev -- --host 0.0.0.0`，在 Safari 访问终端展示的局域网地址。必要时允许 macOS 防火墙的本地网络访问。此方式仅用于开发预览；后续 PWA 的离线能力需在 HTTPS 环境验证。

`dist/` 是后续静态部署的产物。GitHub 仓库用于托管源码，项目网页目前没有部署到公网。

### iPhone 版

需要 Xcode 以及已经安装好的 Node.js。在 Xcode 中打开 `ios/FitTrack.xcodeproj`，选择 `FitTrack` Target，然后在 **Signing & Capabilities** 中选择自己的 Apple Developer Team。选择一台 iPhone 模拟器后点击运行；Xcode 会自动构建网页并打包到 App 中。

模拟器可以验证界面和本地记录。HealthKit 的真实健康数据需要使用实体 iPhone，并在系统授权弹窗中允许 FitTrack 读取。当前版本只完成权限连接，尚未把健康数据自动写入 FitTrack 记录。

## 使用方式与本地数据

1. 首次访问自动进入 `#/onboarding`，填写完整资料，查看计算预览并保存。
2. `#/today` 展示当前业务日期的目标、BMR 和 TDEE。
   记录达到观察条件后，同页会显示动态 TDEE 试算与每日摄入建议；不足时显示当前记录进度。
3. `#/profile` 查看资料，`#/profile/edit` 修改或取消修改。
4. `#/diet` 按四餐记录食物，可选择日期补录；营养字段填写本次实际食用总量，修改重量不会自动换算。
5. `#/training` 记录运动类型、时长和手动估算消耗。
6. `#/weight` 每天保存一条体重，可从今日或我的进入。记录页选择日期，再新增或修改当天体重。
7. `#/trends` 查看以指定日期结束的 7、30 或 90 日体重、摄入、热量差及 7 日平均；图表下方保留精确的每日明细表。
8. `#/backup` 下载完整 JSON 备份，或选择备份文件查看摘要后导入。导入是完整替换，不与当前记录合并。
9. 删除后在同一日期的“最近删除”中恢复，不提供永久清除入口。

数据保存在 IndexedDB 数据库 `fittrack-local` 中，资料、计划快照、体重、饮食、训练和饮食完成状态使用独立对象存储。所有集合在同一个事务中更新，写入失败时保留原状态。首次打开新版时会校验并迁移旧 localStorage 键 `fittrack.state.v1`；只有数据库提交成功后才移除旧副本。损坏数据或不支持的版本不会被自动清空。

食物新增、编辑、删除、恢复会将受影响日期重新标为“记录中”；标记当日记录完成代表当天饮食已完整，包括用户明确确认的零摄入日。未完成日期的热量差是基于当前已记录摄入的临时值。

体重按日期唯一。最新有效体重同步到资料并更新今日计划，补录早于最新记录的日期不会覆盖当前体重。删除最新体重会回退到最近有效记录，恢复后再次更新；全部删除时保留资料中的最后已知体重。所有操作均保留过去日期的计划快照。

业务日期固定使用 `Asia/Shanghai`。打开新一天时生成当日计划，不补造未访问日期或体重；编辑资料只更新当天目标。今日页跨午夜会自动刷新，编辑中的表单不会被定时刷新覆盖。

IndexedDB 事务会串行处理多标签页写入，BroadcastChannel 会通知其他标签页刷新未编辑的页面。本地数据库仍按网站来源隔离，`localhost`、`127.0.0.1`、不同端口和未来线上域名不会自动共用数据；跨来源迁移请使用 JSON 备份。

未加入账号、云同步或遥测。备份文件只在当前设备生成和读取，不会由 FitTrack 上传；文件包含身体、饮食和训练信息，应保存到可信位置。导入成功后只保留最近一次导入前的恢复副本，清除网站数据也会清除该副本，因此长期使用时仍应定期下载外部备份。

## 计算口径

使用 Mifflin–St Jeor 公式估算静息能量消耗，界面沿用“BMR（估算）”。[原始研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)

```text
男性：10 × 体重kg + 6.25 × 身高cm − 5 × 年龄 + 5
女性：10 × 体重kg + 6.25 × 身高cm − 5 × 年龄 − 161
TDEE = BMR × 活动系数
```

| 活动水平 | 系数 |
| --- | --- |
| 久坐 | 1.2 |
| 轻度 | 1.375 |
| 中度 | 1.55 |
| 高度 | 1.725 |
| 极高 | 1.9 |

减脂、维持、增肌的目标分别为 TDEE × 0.85、1、1.10。这些是产品默认策略，不是针对个人的医疗或营养处方。V1 暂限成人；校验范围为年龄 18–100 岁（整数）、身高 100–250 cm、体重 30–350 kg，边界为产品输入约束。

- TDEE 已包含活动水平中的平均训练消耗，训练记录不额外叠加到预计总消耗。
- 热量差 = 摄入 − TDEE；负数表示缺口。
- 距目标剩余 = 目标摄入 − 摄入；负数表示超出目标。
- 食物重量和营养字段均代表实际食用份量；不会用 4/4/9 强行覆盖输入热量。
- 保留内部小数精度，只在 UI 展示时格式化；热量取整数，营养素汇总最多保留一位小数。
- 7 日窗口包含指定日期及前 6 天，按日历计算，不是最近 7 条记录。
- 缺失值用 `null` 表示，不当作零；没有有效数据时平均值为 `null`。
- 摄入平均值由业务层筛选已完成饮食记录的日期后计算，同时展示有效天数。每日数值重复则拒绝计算，避免重复加权。
- 趋势可查看 7、30 或 90 个日历日；为计算窗口开头的 7 日平均，会额外读取此前 6 天，但不会把它们画入所选区间。
- 未完成饮食日期的摄入和热量差以空心点显示，表示临时值；没有当日计划时热量差保持缺失。
- 业务层以 `Asia/Shanghai` 产生日期键，并保存每日目标快照，资料变更不覆盖历史。

动态 TDEE 只使用最近 28 个日历日中已标记完成的饮食记录，以及未删除的体重记录。需要至少 21 天完整饮食、6 次称重、首周和末周各至少 2 次称重，且称重跨度至少 21 天。由体重趋势和平均摄入得到的观察值会向当前 TDEE 基线收缩，并限制调整幅度不超过基线的 10%；变化过快或记录明显不一致时不提供建议。换算中使用的约 7,700 kcal/kg 是粗略经验量，水分变化等会带来误差。建议仅作自我记录的参考，不自动修改每日目标或历史计划，也不叠加训练记录中的消耗。
